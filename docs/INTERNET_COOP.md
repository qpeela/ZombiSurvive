# Кооператив через интернет (T005C)

Маршрут для прототипа — Tailscale на обоих устройствах. Игровой сервер и мир
работают на компьютере хоста; другу нужны браузер и Tailscale. Подключение к
виртуальной сети и одноразовое приглашение в игру — два отдельных шага.

## Подготовка сети

1. Установите [Tailscale](https://tailscale.com/download) на оба устройства
   по [официальной инструкции](https://tailscale.com/docs/install).
   Подключите устройства к одной доверенной tailnet. Используйте отдельные
   учётные записи участников; пароль хоста передавать не нужно.
2. Проверьте, что оба устройства включены и подключены в приложении Tailscale.
   Для хоста нужен обычный сетевой интерфейс с IPv4; режим
   `--tun=userspace-networking` без интерфейса не поддерживается.
3. Узнайте IPv4 хоста через приложение или `tailscale ip -4`. Это адрес из
   `100.64.0.0/10`; возьмите именно адрес хоста, а не друга или DNS `100.100.100.100`.
   На macOS CLI приложения можно вызвать полным путём:
   `/Applications/Tailscale.app/Contents/MacOS/Tailscale ip -4`.
4. На устройстве друга выполните `tailscale ping <IPv4-хоста>`.
   Для игры разрешите в политике доступа Tailscale только доверенным участникам
   TCP на выбранный порт хоста (по умолчанию 3001). При использовании другого
   порта поменяйте правило. Ping проверяет VPN-маршрут; доступ к игре проверьте
   отдельно по HTTP ниже. Учитывайте также firewall ОС хоста.

Не включайте Funnel, публичный proxy, проброс порта на роутере, subnet router
или exit node: для этого сценария они не нужны. Приложение не устанавливает VPN
и не меняет firewall, маршруты или политики вашей сети.

Tailscale использует сквозное шифрование WireGuard и для прямого соединения,
и для relay; relay может увеличить задержку. Контрольная инфраструктура
Tailscale остаётся внешней зависимостью, игровой симуляции у неё нет.
См. [типы соединений](https://tailscale.com/docs/reference/connection-types)
и [политики доступа](https://tailscale.com/docs/features/access-control).

## Запуск игры

На хосте после обычной установки зависимостей:

```sh
npm run build
COOP_NETWORK=tailscale COOP_HOST=100.80.12.34 npm start
```

Замените пример на IPv4 своего интерфейса Tailscale. Для другого порта добавьте
`PORT=3002`. Сервер слушает только выбранный адрес. `COOP_NETWORK` принимает
`lan` (по умолчанию) или `tailscale`; опечатка, отсутствие COOP_HOST в режиме
Tailscale, адрес вне диапазона или без локального интерфейса останавливают запуск.
Solo по-прежнему запускается без обеих переменных на `127.0.0.1`;
LAN — с `COOP_HOST=<private IPv4>`.

Режим `tailscale` — явный выбор оператора. Проверка диапазона и интерфейса
сама по себе не доказывает шифрование: CGNAT-адреса используют и провайдеры.
Перед запуском сопоставьте COOP_HOST с адресом в Tailscale. При конфликте с
другим VPN/провайдером исправьте маршрут; не обходите проверку через wildcard.
Справка: [адреса и конфликты](https://tailscale.com/docs/reference/reserved-ip-addresses).

С устройства друга откройте `http://100.80.12.34:3001/health`: ожидается
`{"status":"ok"}`. Затем хост открывает локальный файл приглашений, путь к
которому напечатан сервером, использует одну ссылку сам и передаёт другую другу
по доверенному каналу. Обе ссылки должны содержать один и тот же IPv4 хоста.
Используйте числовой адрес из приглашения: MagicDNS и другие имена не разрешены
проверкой Host. HTTP и игровой WebSocket используют этот же origin внутри VPN.
HTTPS/WSS и reverse proxy этим режимом не настраиваются.

Приглашения одноразовые, действуют 30 минут; после входа браузер использует
HttpOnly cookie. Не передавайте файл целиком и не публикуйте ссылки в issue,
PR, журналах или скриншотах. Остальные правила идентичности и ограничения
описаны в [README](../README.md#кооператив-в-частной-сети).

При разрыве VPN восстановите маршрут и нажмите «Подключиться снова».
Пока процесс хоста жив, cookie возвращает прежнего персонажа и позицию.
При остановке сервера мир и сессии теряются; после нового запуска нужны новые
приглашения. Для завершения партии нажмите Ctrl+C; для отзыва сетевого доступа
удалите разрешение участника в Tailscale. Удаление доступа к VPN не отзывает
игровую cookie на других доступных маршрутах.

## Реальная приёмка

Автоматические тесты проверяют выбор адреса и отказ неверной конфигурации,
HTTP/WS-авторизацию, двух игроков, движение, reload/retry и остановку хоста.
Loopback и LAN не подтверждают подключение через интернет.

Для приёмки оставьте хоста в домашней сети, а друга подключите к другой сети
(например, через мобильную точку доступа с выключенным домашним Wi-Fi).
На обоих устройствах включите Tailscale и проверьте:

1. Health и вход по разным приглашениям; два разных персонажа в одном мире.
2. WASD каждого меняет только его персонажа; оба видят движение другого.
3. Reload сохраняет персонажа и позицию.
4. Отключение VPN у друга приводит к потере связи; после включения ручной retry
   возвращает прежнего персонажа. Без приглашения новый профиль не входит.
5. Ctrl+C хоста отключает обоих; после рестарта старые сессии не входят.

Запишите дату, ОС и браузеры, разные физические сети, результат шагов,
тип соединения (`direct`/`relay`, если известен) и замеченную задержку.
Не записывайте секреты. Пока эта проверка не подтверждена, T005C не завершена.
