# Приёмка одиночного цикла — T040

Дата: 14 ноября 2026 года. База: main d6de789 (T039 / PR #46).
[PR #47](https://github.com/qpeela/ZombiSurvive/pull/47), ветка codex/t040-solo-acceptance. Локальные проверки успешны; нужен Quality финального коммита до merge.

## Воспроизведение

Node 24.19.0, установленный Chromium Playwright и собранные приложения:

```sh
npm run build
npx playwright test tests/smoke/solo-acceptance.spec.mjs
npm run check
```

Сценарий сам создаёт отдельное временное SQLite-сохранение и localhost-хост
127.0.0.1:3136; освобождает процесс/вкладку/сохранение и при ошибке. Порт должен
быть свободен. Production-файлы, контракты и баланс T040 не меняет.

Для ручного повторения создайте пустой временный каталог, задайте абсолютный
WORLD_SAVE_PATH внутри него и выполните:

```sh
WORLD_SAVE_PATH=/tmp/zombi-acceptance/world.sqlite node tests/fixtures/solo-acceptance-host.mjs
```

Откройте http://127.0.0.1:3136. Это только тестовый хост. Он использует настоящий
LocalWorldRoom, SoloWorldStore и startLocalServer с собранным клиентом; нет HTTP
API для изменения игры, подмен браузерных API, телепортации, выданного тестом
снаряжения или искусственного урона. Начальный мир и действия обычные.

Для воспроизводимости тестовый процесс передаёт существующим часам Room/Store
Date.now() + offset. На синхронное создание Room он также задаёт seeded RNG
(LCG, seed=1), который захватывает LocalWorldCombat вместо обычного Math.random;
глобальная функция сразу восстанавливается. Первый бросок 0,236 попадает в
обычную вероятность ранения 25%. Так этап с бинтом не зависит от удачи. Правила
урона/ранения не меняются; обычный запуск игры использует прежнюю случайность.
Глобальные Date.now, SDK/auth-часы и скорость 20 шагов/с не подменяются.

## Связный маршрут

1. Сохранить имя, войти в полный экран и выйти кнопкой. Экипировать топор,
   дойти до бинта (2, 2), подобрать его.
2. Войти в обычный радиус обнаружения зомби (-3, 0), получить настоящее ранение.
   Два удара топора с паузой 1,2 с наносят 60 + 40 HP. Проверить отрисовку оружия,
   подтверждённый эффект и убийство. Использовать бинт: рана исчезает, HP не растёт.
3. Дойти до (-10, -6), подобрать/экипировать пистолет и пачку 9 мм. Четыре
   прицельных выстрела в зомби у (-24, 0) дают 30 + 30 + 30 + 10 HP. ПКМ,
   пробел и кнопка HUD доступны; ЛКМ остаётся движением. R запускает реальный
   таймер 2 с: магазин 4 → 8, пачка 8 → 4.
4. Остаться у места стрельбы: другие зомби услышат её, подойдут и убьют игрока.
   Проверить 0 HP, экран смерти и тело с шестью вещами. Остановить и запустить
   хост, перезагрузить страницу: смерть сохраняется, автоматического respawn нет.
5. Явно возродиться: 100 HP, новая lifeRevision=1, пустое снаряжение, прежнее имя.
   Вернуться к телу, забрать пистолет/экипировать и пачку ×4. Оставить четыре
   стартовых melee-предмета в теле. Уйти спринтом на юг (до y ≥ 8), остановить и
   запустить хост в безопасной точке для последующих проверок сохранения.
6. В stdin тестового хоста послать одну строку:
   `{"advanceMs":86400001}`. Дождаться clock-advanced и новых шагов мира.
   Остановить хост: сырое поле corpses в SQLite уже пусто до открытия Store;
   четыре оставленные вещи — expired, возвращённые пистолет 8/8 и пачка ×4 целы.
   При перезапуске передать `SOLO_ACCEPTANCE_CLOCK_OFFSET_MS=86400001`.
7. Перезагрузка страницы, две вкладки одного персонажа, offline/reconnect,
   SIGKILL и повторный запуск сохраняют имя, одну новую жизнь, пистолет 8/8 и
   единственную пачку ×4. Тело и оставленные вещи не появляются заново.

При остановках хоста используется обычный graceful shutdown либо SIGKILL;
приостановки AI/процесса и изменения состояния зомби не применяются. Между
ударами/выстрелами автоматический сценарий ждёт реальные подтверждённые тики,
движение — подтверждённую позицию с допуском 0,05 м на пиксельную точность.
Бюджет сценария 120 с обоснован ходьбой, двумя боями и естественной смертью;
retries=0, skipped отсутствуют.

## Наблюдения и границы

- Полный npm run check прошёл: формат/lint, типы, архитектура и сборки;
  617 unit + 17 tooling + 20 contract + 79 smoke = 733 теста без skipped,
  smoke — 8,2 минуты. Сквозной сценарий внутри полного набора — 47,7 с.
  Отдельный прогон с seeded RNG — 46,9 с. Diff и локальные ссылки проверены;
  все шесть ключевых снимков осмотрены. Runtime-исправления не потребовались.
- Ручной сквозной маршрут пройден через CUA во встроенном браузере на отдельном
  пустом сохранении: имя «Ручная приёмка», найденный бинт, два удара топора,
  перевязка без лечения (39 HP), ПКМ + три пробела, reload до 8/8 и пачки ×4,
  естественная смерть, restart с 0 HP, явный respawn, возвращённые пистолет/пачка,
  спринт на юг, две вкладки и reload/переподключение после остановки хоста.
  После clock-advance работающий хост записал corpses=[], четыре expired-метки,
  сохранённые gun8/revision5 и pack4; итог — 100 HP, lifeRevision=1, прежнее имя.
  Первый ручной заход завершился ранней смертью во время осмотра; маршрут
  повторён на новом пустом мире без паузы AI. Это не падение автоматического теста.
- Ручной встроенный браузер отказал в requestFullscreen: UI сообщил об отказе,
  игра продолжила работу. Настоящий полный экран и доступность HTML UI успешно
  проверены в отдельном Chromium автоматического сценария.
- HP/популяция и интерес зомби временные (T029); restart восстанавливает исходных
  зомби. Поэтому при возврате к телу после рестарта встречается исходная популяция.
- Срок тела — реальные 24 часа, ускорены только часы тестового сохранения. После
  отхода тела нет в видимости 8 м: истечение подтверждает запись работающего хоста
  в SQLite и последующий reload, а не исчезновение дальнего маркера в том же кадре.
- Бинт не лечит. Дополнительные удары/кровотечение могут уменьшать HP во время
  осмотра, поэтому живое HP не сравнивается с произвольной прежней секундой.
- LAN/интернет, кооператив, нагрузочная ёмкость, восстановление лута и постоянная
  популяция зомби не входят в приёмку. T005C/T014C остаются PAUSED.

### Среда и воспроизведение

Проверяется production-сборка Phaser/Vite и Node/Colyseus, HTTP и WebSocket
на loopback одного компьютера. Node.js 24.19.0 из `.nvmrc`, npm workspace,
Chromium из Playwright 1.64.0. Локальный запуск — macOS; CI Quality — Ubuntu.
Клиент и сервер собраны вместе, wire-протокол v5, генератор v1, SQLite-схема v1.

```sh
npm ci
npx playwright install chromium
npm run check
```

Если Chromium установлен в `.cache/playwright`, перед командами задайте
`PLAYWRIGHT_BROWSERS_PATH=.cache/playwright`.
Отдельная проверка сквозной приёмки после `npm run build`:

```sh
npm run test:smoke -- tests/smoke/solo-persistence.spec.mjs
```

Тест запускает реальный собранный сервер, который раздаёт клиент с same-origin.
SQLite создаётся во временном каталоге; игровой `.local/solo.sqlite` не открывается.
Все процессы и временные файлы освобождаются в `finally`. Фиксированные порты
3109/3110 и порты общего Playwright-конфига должны быть свободны.
Ожидания опираются на статус, подтверждённые координаты и tick, без `sleep`.

### Ограничения принятого прототипа

- Это solo-срез технического прототипа. Нет лута/инвентаря, зомби, боя, здоровья
  и игрового цикла выживания. Следующая карточка — T015; в T014 она не реализуется.
- Нет автоматического поиска пути: цель за стеной остаётся активной до отмены;
  обход выполняется вручную. Прицел визуальный, без стрельбы; шум пока не влияет на AI.
- Terrain декоративный; коллизии статические, между персонажами столкновений нет.
  Мир — повторяемые руины/камни v1, без дорог, регионов и сохранения изменений чанков.
- Только solo сохраняет ID/позицию и ключ генератора. Stamina/ввод/ack при запуске
  сбрасываются. После аварии возможен откат до последнего commit: обычно до секунды,
  при задержке event loop — дольше. Синхронный SQLite fsync может задержать симуляцию.
  Миграции, автоматические бэкапы и измерения дисковой задержки отложены.
- Клиент и сервер требуют совместной сборки. При сетевой задержке возможны видимые
  коррекции; без snapshots предсказание замирает через 0.5 секунды. Это не оценка FPS
  или субъективной отзывчивости на разных компьютерах.
- Проверены автоматизированные сценарии Chromium на одном компьютере и отдельные
  серверные процессы. Другие браузеры, реальные устройства, длительная игра,
  сон/пробуждение ОС, дефицит ресурсов и нагрузка не проверялись.
- Существующие кооперативные регрессии остаются в полном наборе тестов, но не
  подтверждают LAN/интернет-приёмку. T005C/T014C остаются PAUSED; Tailscale не нужен.

Для обычного запуска и работы с сохранением используйте [README](../README.md).
