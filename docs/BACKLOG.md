# Очередь небольших задач

Режим: ручной, подтверждён пользователем. Команда запуска:
«Сделай следующую задачу». Автоматическое расписание не требуется.
Требования: [GAME_DESIGN.md](../GAME_DESIGN.md).
Текущее состояние: [PROGRESS.md](PROGRESS.md).
Архитектура: [ARCHITECTURE.md](ARCHITECTURE.md), кодстайл: [CODE_STYLE.md](CODE_STYLE.md).
Завершение через GitHub PR и CI: [PR_PROCESS.md](PR_PROCESS.md).

чтобы не блокировать лут, инвентарь, зомби и бой.

## Правила одного запуска

1. Прочитать краткий прогресс, карточку задачи и относящиеся к ней требования.
2. Выбрать одну готовую задачу с выполненными зависимостями.
   Если есть незавершённая задача, сначала продолжить её, кроме PAUSED.
3. Работать одним агентом; подагенты для этого режима по умолчанию не нужны.
4. Реализовать цель и выполнить необходимые проверки её результата.
   Не добавлять соседние возможности и необязательные рефакторинги.
5. Выполнить проверки, опубликовать отдельный PR и подтвердить результат CI
   по PR_PROCESS.md. Обновить статус задачи и краткий прогресс.
6. После публикации результата не начинать следующую задачу в том же запуске
   без отдельного поручения пользователя. Зависимые задачи ждут слияния PR.

Если задача оказалась широкой, разделить её на самостоятельные части с
отдельными критериями готовности. Не считать частично работающую систему
завершённой и не пропускать необходимые проверки ради уменьшения расхода.
При внешнем блокере записать его и не помечать задачу DONE.

Номера обозначают порядок задач, а не гарантированный календарный план.
Одна задача обычно меняет одно поведение. Маленькие изменения часто затрагивают
несколько файлов; число строк или файлов само по себе не определяет сложность.

## Статусы

- READY — карточка описана, зависимости выполнены.
- DRAFT — следующий шаг намечен, карточку нужно уточнить перед выполнением.
- IN_PROGRESS — начата; следующий запуск продолжает её.
- CI_PENDING — PR опубликован, CI ещё не подтверждён.
- IN_REVIEW — PR опубликован, локальные и обязательные CI-проверки прошли.
- BLOCKED — есть конкретное препятствие, оно записано в прогрессе.
- PAUSED — отложена по явному поручению пользователя; не блокирует независимые
  задачи и возобновляется только по отдельному поручению.
- DONE — критерии выполнены, проверки записаны, PR слит в main.

магазине как состояние конкретного экземпляра; редкий лут и сохранение состояния.
Характеристики и видимый счётчик согласовать перед реализацией.

**Не входит:** выстрел, перезарядка, съёмные магазины и новые слоты.

**Готовность:** пистолет перемещается между миром, сеткой, руками и телом
без изменения ID/боезапаса; смена оружия и рестарт не пополняют магазин.

**Проверки:** границы ёмкости, экипировка, смерть/тело, подбор и восстановление старого сохранения.

### T037 — одиночный выстрел из пистолета

Статус: DRAFT. Зависимости: T036.

**Цель:** поражать зомби прицельным выстрелом с расходом патрона.

**Область:** content/protocol/simulation, серверный бой/хранение, клиентский прицел/ввод/эффекты, тесты.

**Входит:** отдельное действие стрельбы, передача проверяемого направления прицела,
серверная трассировка до первого препятствия/зомби, урон, дальность, cooldown
и атомарное списание одного патрона. Клик движения сохраняется; управление уточнить явно.

**Не входит:** автоматический огонь, баллистика, PvP, перезарядка и привлечение звуком.

**Готовность:** стены останавливают пулю, пустой магазин не стреляет, промах
тратит патрон; клиент не задаёт цель/урон. Дубли команд не создают лишний выстрел.

**Проверки:** направление/дальность/стены, несколько целей на луче,
две вкладки, смена оружия, 0 HP, сохранение боезапаса и эффекты попадания.

### T038 — патроны и перезарядка

Статус: DRAFT. Зависимости: T037.

**Цель:** пополнять магазин подходящими патронами из инвентаря.

**Область:** content/protocol/simulation, серверные лут/сохранения, инвентарь/HUD, тесты.

**Входит:** пачка патронов как предмет с количеством, мировой лут,
действие перезарядки с серверной длительностью и индикатором; перенос нужного
количества в магазин одной транзакцией. Правила отмены при смерти/смене оружия фиксируются явно.

**Не входит:** разные калибры оружия, съёмные магазины и поштучные анимации.

**Готовность:** полный магазин не расходует патроны; частичная пачка работает,
стрельба во время перезарядки запрещена. Повтор, retry, отмена и рестарт
не создают боезапас и не списывают его дважды.

**Проверки:** полный/пустой магазин, нехватка патронов, неверный тип,
одновременные команды, прерывание и сбой записи.

### T039 — зомби реагируют на выстрелы

Статус: DRAFT. Зависимости: T037.

**Цель:** стрельба привлекает ближайших зомби к источнику шума.

**Область:** content/simulation, серверные события боя/AI, UI при необходимости, тесты.

**Входит:** шум только от разрешённого выстрела, радиус/срок интереса,
движение к услышанной точке с существующим обходом препятствий и переход
к преследованию при обнаружении игрока. Баланс согласуется с шумом T010.

**Не входит:** новый тип зомби, симуляция дальних чанков, стереозвук и новая система слуха для всех действий.

**Готовность:** зомби в радиусе реагирует, вне радиуса — нет; пустой магазин
и отклонённая команда не привлекают. Повтор события не продлевает интерес бесконечно,
выгрузка чанка и потеря цели корректны.

**Проверки:** граница радиуса/времени, несколько выстрелов, стены/навигация,
смена состояния AI и активность только рядом с игроком.

### T040 — приёмка полного одиночного цикла

Статус: DRAFT. Зависимости: T021–T039.

**Цель:** подтвердить связный цикл «найти вещи → сразиться → перевязаться →
умереть → возродиться → вернуть вещи» в собранной игре.

**Область:** tests/smoke, docs/SOLO_ACCEPTANCE.md, BACKLOG.md/PROGRESS.md;
исправления найденных дефектов оформляются отдельными узкими карточками.

**Входит:** один воспроизводимый solo-сценарий с именем, полноэкранным режимом,
анимацией оружия, melee/стрельбой/перезарядкой, сохранениями и сроком тела.
Проверить reload, потерю соединения, две вкладки и остановку/рестарт хоста.

**Не входит:** LAN/интернет-приёмка, новые механики, обещания нагрузочной ёмкости и весь этап окружения.

**Готовность:** сценарий пройден автоматически и вручную, результат и ограничения
записаны; критичные дефекты исправлены и перепроверены, skipped не считается успехом.

**Проверки:** полный npm run check и Quality, управляемое время для срока тела,
ручная игра и осмотр снимков ключевых состояний.

## Экономия контекста

В PROGRESS.md держим только текущее состояние, нужные решения и следующий шаг.
Не копируем туда полные логи или всю историю чата. Исходный код и требования
остаются источником истины. Читаем соседние файлы по необходимости.
После фиксации версии библиотеки не повторяем поиск её документации без причины.

Расписание распределяет расход по дням, но не уменьшает общий расход само по себе.
Экономия достигается узким scope, коротким контекстом и отсутствием лишних агентов.
Размер задачи не гарантирует точное число токенов; численный бюджет в этом
режиме пока не задан.
