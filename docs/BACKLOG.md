# Очередь небольших задач

Режим: ручной, подтверждён пользователем. Команда запуска:
«Сделай следующую задачу». Автоматическое расписание не требуется.
Требования: [GAME_DESIGN.md](../GAME_DESIGN.md).
Текущее состояние: [PROGRESS.md](PROGRESS.md).
Архитектура: [ARCHITECTURE.md](ARCHITECTURE.md), кодстайл: [CODE_STYLE.md](CODE_STYLE.md).
Завершение через GitHub PR и CI: [PR_PROCESS.md](PR_PROCESS.md).

чтобы не блокировать лут, инвентарь, зомби и бой.

## Правила одного запуска

1. Прочитать краткий прогресс, карточку задачи и относящиеся к ней требования.
2. Выбрать одну готовую задачу с выполненными зависимостями.
   Если есть незавершённая задача, сначала продолжить её, кроме PAUSED.
3. Работать одним агентом; подагенты для этого режима по умолчанию не нужны.
4. Реализовать цель и выполнить необходимые проверки её результата.
   Не добавлять соседние возможности и необязательные рефакторинги.
5. Выполнить проверки, опубликовать отдельный PR и подтвердить результат CI
   по PR_PROCESS.md. Обновить статус задачи и краткий прогресс.
6. После публикации результата не начинать следующую задачу в том же запуске
   без отдельного поручения пользователя. Зависимые задачи ждут слияния PR.

Если задача оказалась широкой, разделить её на самостоятельные части с
отдельными критериями готовности. Не считать частично работающую систему
завершённой и не пропускать необходимые проверки ради уменьшения расхода.
При внешнем блокере записать его и не помечать задачу DONE.

Номера обозначают порядок задач, а не гарантированный календарный план.
Одна задача обычно меняет одно поведение. Маленькие изменения часто затрагивают
несколько файлов; число строк или файлов само по себе не определяет сложность.

## Статусы

- READY — карточка описана, зависимости выполнены.
- DRAFT — следующий шаг намечен, карточку нужно уточнить перед выполнением.
- IN_PROGRESS — начата; следующий запуск продолжает её.
- CI_PENDING — PR опубликован, CI ещё не подтверждён.
- IN_REVIEW — PR опубликован, локальные и обязательные CI-проверки прошли.
- BLOCKED — есть конкретное препятствие, оно записано в прогрессе.
- PAUSED — отложена по явному поручению пользователя; не блокирует независимые
  задачи и возобновляется только по отдельному поручению.
- DONE — критерии выполнены, проверки записаны, PR слит в main.

После фиксации версии библиотеки не повторяем поиск её документации без причины.

Расписание распределяет расход по дням, но не уменьшает общий расход само по себе.
Экономия достигается узким scope, коротким контекстом и отсутствием лишних агентов.
Размер задачи не гарантирует точное число токенов; численный бюджет в этом
режиме пока не задан.
