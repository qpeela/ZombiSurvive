# ZombiSurvive

Браузерная 2D-игра о выживании в мире с зомби. Браузер подключается к локальному
миру через Colyseus/WebSocket. WASD перемещает видимого персонажа;
Phaser предсказывает своё движение, UI показывает подтверждённую сервером позицию. Сервер вызывает общий
расчёт движения packages/simulation с фиксированным шагом 20 Гц (T004–T005).
Целевая модель — одиночная игра и кооператив с друзьями, локальный сервер
на компьютере игрока-хоста без аренды выделенного сервера. T005B добавляет явный
кооператив по приглашениям в доверенной частной сети. Требования:
[ADR 0001](docs/adr/0001-local-host-coop.md).

С 16 октября 2026 года текущий этап разработки — одиночная игра. Кооператив
и его интернет-приёмка поставлены на паузу; подготовленный код сохранён.
Для solo Tailscale не нужен: после сборки используйте обычный `npm start`.

## Установка и запуск собранной игры

Использовать Node.js из .nvmrc и npm. С nvm:

```sh
nvm install
nvm use
npm ci
npm run build
npm start
```

Откройте http://127.0.0.1:3001/ в браузере хоста. Один сервер раздаёт собранный
клиент и обслуживает игровой HTTP/WebSocket на том же origin; Vite для игры не нужен.
После первой сборки для последующих запусков достаточно `npm start`; после изменения
исходников повторите `npm run build`. Ctrl+C завершает сервер и отключает игроков.
Проверка сервера: http://127.0.0.1:3001/health. Порт можно изменить:
`PORT=3002 npm start`, затем открыть http://127.0.0.1:3002/.
Если клиент не собран, сервер сообщает о необходимости выполнить `npm run build`.
Используйте адрес с 127.0.0.1: проверка Host не разрешает произвольные имена хоста.
Без COOP_HOST доступен только локальный solo. Публичное размещение не настроено.

В новом solo-мире персонаж появляется в центре метровой сетки, в позиции (0, 0 м).
При повторном запуске сервер восстанавливает сохранённую позицию.
Кнопка «На весь экран» разворачивает игровое поле вместе с HUD, инвентарём
и боевыми кнопками. «Выйти из полного экрана» или Esc возвращает окно.
Если браузер запрещает режим, рядом с кнопкой появится сообщение.

WASD работает по физическим клавишам независимо от раскладки; противоположные
клавиши отменяют друг друга. Скорость 4 м/с, диагональ не быстрее оси.
Отпускание клавиш, потеря фокуса и скрытие вкладки останавливают движение.
Камера следует за персонажем и удерживает его в центре; сетка продолжается
при движении в любую сторону. Курсор задаёт локальный прицел и указатель направления.
Левый клик по полю задаёт точку назначения, отмеченную зелёным кольцом. Персонаж
идёт по прямой с обычной скоростью и точно останавливается в точке; новый клик
меняет её, WASD отменяет цель. Клики по интерфейсу не управляют персонажем.
Потеря фокуса, скрытие вкладки и разрыв связи отменяют цель; reload/retry
сохраняют серверную позицию, но не возобновляют движение. Прицел пока визуальный,
стрельбы и автоматического поиска пути нет.
Серые стены и ящик непроходимы: сервер учитывает квадрат персонажа 0.7 × 0.7 м,
останавливает его у грани и позволяет скользить вдоль неё. Клик за стену или внутрь
блока оставляет цель активной: для обхода используйте WASD или промежуточные клики.
Свой персонаж и камера сразу реагируют на WASD/клик благодаря клиентскому
предсказанию с теми же правилами движения и столкновений. Сервер исправляет
позицию; при задержке возможны видимые поправки. Без новых snapshots предсказание
замирает через 0.5 секунды. Переподключение очищает его историю; другие персонажи
показываются по серверным позициям.
Shift (с любой стороны клавиатуры) включает спринт для WASD и движения к точке:
скорость 7 м/с вместо 4 м/с, с нормализованной диагональю. Индикатор на поле
показывает выносливость. Полный запас расходуется за 5 секунд спринта;
ходьба и покой восстанавливают его за 10 секунд от нуля. После истощения
спринт недоступен до 20%, затем удерживаемый Shift снова включает его.
Попытка спринта в стену расходует запас, Shift в покое — нет. Смена Shift
не отменяет цель. Сервер хранит запас между reload/retry, пока жив процесс;
клиент предсказывает его вместе с движением. После пересборки протокола v5
перезапускайте клиент и сервер вместе.
Ctrl (левый или правый) включает скрытность для WASD и левого клика: скорость
2 м/с и радиус шума 2 м вместо 8 м при ходьбе и 16 м при спринте. Ctrl имеет
приоритет над Shift; выносливость восстанавливается. Режим не отменяет цель,
в покое и при полной блокировке стеной шум нулевой. HUD показывает режим и шум;
персонаж приседает. Потеря фокуса/связи сбрасывает Ctrl. Это начальный баланс;
радиус пока не влияет на зомби и не создаёт аудиоэффекты.
Перезагрузка страницы и повторный вход возвращают того же solo-персонажа
на текущую серверную позицию. Несколько локальных вкладок представляют одного
игрока: последний ненулевой ввод получает управление, чужая остановка его не отменяет.
При потере связи движение прекращается; без свежего ввода оно ограничено 0.5 секунды
симуляции.

## Сохранение одиночного мира

Solo-сервер сохраняет ID мира, ID персонажа и его подтверждённую позицию
в `.local/solo.sqlite` в корне проекта, независимо от рабочего каталога запуска.
Перезапуск, другой порт и новый профиль браузера возвращают того же персонажа.
Намерения движения и ack сбрасываются; выносливость восстанавливается до полной.
Чанки вновь генерируются из сохранённых seed/версии; изменения мира пока не сохраняются.

Автосохранение выполняется раз в секунду вне шага симуляции; Ctrl+C/SIGTERM
записывает последнюю позицию перед остановкой. После аварийного завершения возможен
откат до последней успешной записи (обычно до секунды, при задержке event loop — дольше).
При ошибке записи сервер сообщает причину и завершает работу с ненулевым кодом.
Повреждённое или несовместимое сохранение останавливает запуск и не заменяется новым.
Один файл может использовать только один сервер; второй запуск отклоняется.

Для отдельного мира задайте абсолютный путь: `WORLD_SAVE_PATH=/absolute/path/world.sqlite npm start`.
Dev-режим использует тот же файл по умолчанию: для отдельного dev-мира задайте
WORLD_SAVE_PATH. Для новой игры укажите новый путь либо после остановки сервера
переместите прежний файл в безопасное место. Файл не раздаётся через HTTP и исключён
из Git. Не копируйте активную БД; остановите сервер перед ручным копированием.
В Node 24 используется встроенный node:sqlite, без новой зависимости.
Кооперативные персонажи, приглашения и сессии пока остаются только в памяти;
кооператив этот solo-файл не открывает.

## Кооператив в частной сети

После сборки выберите IPv4-адрес сетевого интерфейса компьютера хоста в своей
доверенной LAN и явно запустите кооператив, например:

```sh
COOP_HOST=192.168.1.239 npm start
```

Адрес должен принадлежать локальному интерфейсу и диапазону 10.x.x.x,
172.16–31.x.x или 192.168.x.x. Сервер слушает только выбранный адрес, отклоняет
wildcard/public/loopback в COOP_HOST и не меняет настройки роутера или firewall.
PORT по-прежнему задаёт порт игры. Dev-режим не разрешает COOP_HOST.

Терминал показывает адрес игры и `Invitations file: .../invitations.json`.
Откройте этот локальный файл: первую ссылку используйте в браузере хоста,
другую передайте другу. Друг открывает её на своём устройстве в той же частной сети;
сервер на его устройстве не нужен. Сам адрес игры без приглашения не даёт войти.
При проблемах проверьте доступность адреса хоста и разрешения firewall своей ОС.

Каждое приглашение одноразовое и действует 30 минут с запуска сервера. Файл
создаётся с правами 0600 в отдельном временном каталоге и удаляется при штатной
остановке. Приглашения и cookie не выводятся в журналы и не раздаются через HTTP.
Передавайте только одну нужную ссылку; не публикуйте файл целиком.
Секрет находится во fragment ссылки и удаляется клиентом из URL до входа;
сервер обменивает его на HttpOnly SameSite=Strict cookie. Уже вошедший браузер
сохраняет свою идентичность при открытии другого приглашения, не расходуя его.

У разных браузеров свои персонажи в одном мире; зелёный «Вы» — ваш персонаж,
голубые «Друг» — остальные. WASD управляет только своим персонажем. Reload и
ручной retry используют cookie и возвращают его прежнюю позицию. Вкладки одного
профиля делят персонажа; очистка cookie или другой профиль требуют нового
неиспользованного приглашения. Идентичность не зависит от IP участника.
Отключённые персонажи остаются в мире на последней серверной позиции;
движение прекращается. При остановке сервера связь теряют все участники.

Ограничения прототипа: до 8 персонажей и 16 одновременных подключений; это границы
ресурсов, а не подтверждённая нагрузочными измерениями вместимость. Все позиции,
сессии и приглашения живут только до остановки процесса. Для новой партии
приглашений требуется перезапуск; сохранения и управление приглашениями из UI
пока отсутствуют. HTTP/WS используется только в доверенной частной сети.
Для интернет-подключения добавлен явный режим Tailscale:
`COOP_NETWORK=tailscale COOP_HOST=<IPv4-интерфейса-Tailscale> npm start`.
Подготовка сети, ограничения и реальная приёмка —
[кооператив через интернет](docs/INTERNET_COOP.md).

## Режим разработки

`npm run dev` запускает Vite на http://127.0.0.1:5173 и сервер на порту 3001.
Оба процесса завершаются по Ctrl+C. В этом режиме сборка клиента не требуется;
сервер не раздаёт статические файлы.

Отдельный запуск: npm run dev --workspace @zombi-survive/client или
npm run dev --workspace @zombi-survive/server. Порт сервера задаётся через PORT.
При изменении порта сервера задайте его адрес в GAME_SERVER_URL для Vite.
Клиент получает игровой endpoint от origin страницы, Vite проксирует HTTP matchmaking
и WebSocket на локальный сервер. GAME_SERVER_URL используется только конфигурацией
Vite, а не кодом браузера. Сервер проверяет Host и Origin; CLIENT_ORIGIN задаёт
дополнительный разрешённый адрес клиента (по умолчанию http://127.0.0.1:5173
в dev; при `npm start` разрешён только origin самого сервера).
Для нестандартных портов:

```sh
PORT=3002 GAME_SERVER_URL=http://127.0.0.1:3002 npm run dev
```

При потере связи UI сообщает об этом. После восстановления хоста нажмите
«Подключиться снова». Подключение ограничено тайм-аутом 10 секунд;
автоматическое восстановление связи пока не реализовано.

## Проверки

Установить Chromium для smoke-тестов один раз, затем выполнить общий набор:

```sh
npx playwright install chromium
npm run check
```

Отдельные команды:

```sh
npm run format
npm run format:check
npm run lint
npm run typecheck
npm run architecture:check
npm run build
npm run test:unit
npm test
```

Smoke-тесты требуют актуальной сборки: npm run build перед npm run test:smoke.
Общий npm run check делает это автоматически. Тесты используют отдельные порты
4173, 3101, 3102, 3103, 3104, 3105, 3106, 3107 и 3108, запускают собственные приложения и не переиспользуют чужие процессы.
Если порты заняты, освободить их или согласованно поменять playwright.config.mjs.

GitHub Actions устанавливает зависимости и Chromium и выполняет npm run check:
форматирование, lint, типы (включая unit-тесты), архитектуру, семь сборок,
Vitest-тесты движения и серверного адаптера, тесты ограничений, контракты
и браузерные/SDK-сценарии движения и подключения. Проверки собранной игры запускают
серверный production entrypoint, открывают страницу непосредственно на сервере и проверяют same-origin
движение, раздачу HTML/JS/CSS, HEAD, недопустимые пути и Host/Origin.
Отдельный запуск контрактных тестов после сборки:
`npm run test:contracts`. Корневые build/lint/typecheck собирают общие пакеты первыми;
перед отдельными typecheck или тестами после чистой установки выполнить
`npm run build:core` (domain → protocol → content → simulation → worldgen).
`build:contracts` по-прежнему собирает только domain/protocol.

## Проверка клиента через Vite preview

Основной запуск собранной игры — `npm start`, как описано выше.
Отдельный режим проверки Vite proxy:

```sh
npm run build
CLIENT_ORIGIN=http://127.0.0.1:4173 npm run start --workspace @zombi-survive/server
```

В другом терминале: npm run preview --workspace @zombi-survive/client,
затем открыть http://127.0.0.1:4173. Vite preview предназначен для локальной
проверки сборки. Он не нужен для обычного запуска игры.

Сервер при старте загружает в память `apps/client/dist/index.html` и JS/CSS
из `apps/client/dist/assets`; изменение сборки требует перезапуска сервера.
Другие файлы, source maps, символьные ссылки внутри assets и неизвестные маршруты
не раздаются. Ответы не кешируются браузером, чтобы повторный запуск после пересборки
не оставлял старый HTML или bundle. Это запуск прототипа у хоста; TLS и сохранения
пока не реализованы. Кооператив включается явно через COOP_HOST;
интернет-маршрут Tailscale требует отдельной настройки и реальной приёмки.

Phaser включён в локальный bundle, сторонние графические ассеты не используются.
Текущий bundle клиента с Phaser и Colyseus около 410 kB gzip; Vite сообщает о chunk больше 500 kB
без сжатия. Оптимизацию загрузки выполняем отдельно после появления игрового контента.

### Процедурные участки и загрузка соседей (T011–T012)

Мир состоит из участков 64 × 64 м: трава, земля, гравий, руины
и процедурные непроходимые камни. Seed `zombi-survive` и версия
генератора `1` фиксированы в общей сборке; сервер, предсказание и отрисовка
используют одинаковую геометрию. Пересобирайте клиент и сервер вместе.
Клиент держит окно 3 × 3 чанка вокруг персонажа, включая отрицательные координаты:
можно пересекать границы, дальние данные и графика освобождаются, при возвращении
местность воспроизводится. Препятствия соседей блокируют и сервер, и предсказание.
Reload возвращает персонажа на ту же позицию, пока работает хост; потеря соединения
очищает клиентское окно. Сервер держит объединение окон персонажей (до 72 чанков).
Генерация локальная и синхронная; геометрия не передаётся по сети.
Сохранений, изменения мира и настройки seed пока нет.

Smoke-тесты используют отдельные временные SQLite-файлы и не открывают `.local/solo.sqlite`.
T013 проверяет штатный рестарт, аварийный SIGKILL, смену порта/профиля/рабочего каталога,
блокировку второго сервера и отказ при повреждении/ошибке записи.

### Подбор предмета (T015)

В стартовом участке есть один бинт в точке (2, 2) м. Подойдите к нему ближе
чем на 1,5 м (WASD или левым кликом) и нажмите «Подобрать бинт». Сервер переносит
его в простой контейнер, убирает с земли и не выдаёт повторно. Reload и повторное
подключение сохраняют предмет, пока сервер работает. Бинт пока нельзя использовать.

Вещи ещё не записываются на диск: после остановки/рестарта сервера контейнер
пуст, бинт снова у старта.

### Сетка инвентаря (T016)

Контейнер содержит 4 × 3 ячейки и вмещает до 2000 г. Бинт занимает 2 × 1 ячейки
и весит 100 г. Нажмите «Переместить бинт», затем выберите верхнюю левую ячейку
мышью или Tab/Enter. Повторное нажатие кнопки отменяет выбор. Занятые клетки
подсвечены; после допустимого переноса сервер подтверждает новое размещение.
Выход за сетку, пересечение и превышение массы отклоняются без потери вещи.

Сейчас в мире остаётся один бинт; правила заполнения и пересечения нескольких
вещей проверяются unit-тестами. Поворот, drag-and-drop, экипировка и применение
ещё не реализованы. Масса пока не влияет на движение. Offline очищает сетку,
retry/reload восстанавливает размещение в течение жизни сервера; после рестарта
вещи не сохраняются. Параметры контейнера и предметов находятся в content.

### Медленный зомби (T017)

Стартовый зомби начинает в (-8, 0) м. В каждом чанке 64 × 64 м появляется
девять зомби со стабильными ID, включая дальние области и отрицательные координаты.
Они движутся со скоростью 1,5 м/с.
Он замечает ближайшего подключённого игрока в пределах 12 м при прямой
видимости; стены закрывают обзор. После обнаружения преследует до 18 м,
обходит статические препятствия и останавливается в 0,9 м от игрока.
Для проверки обойдите восточную стену через её конец: зомби последует вокруг
руин. Его положение подтверждает сервер; коричневый маркер подписан «Зомби».

Поиск пути ограничен окном между зомби и целью с запасом 4 м. Если обход
не найден, зомби стоит. Без подключённых игроков поблизости AI не движется;
при потере связи маркер исчезает, retry/reload восстанавливает его.
Зомби не слышит шум. Убитые зомби не появляются повторно при возврате в область
в течение работы хоста. После остановки хоста популяция и здоровье зомби сбрасываются.
После загрузки сохранённой позиции зомби появляются и в удалённой области.

### Атака зомби и здоровье (T018)

В HUD отображается подтверждённое сервером здоровье: начальные 100 HP.
Зомби наносит 10 урона после секунды непрерывной досягаемости в пределах
1,1 м. Стены блокируют удар; выход из радиуса или смена цели прерывают замах.
Несколько вкладок одного персонажа получают общее здоровье и не ускоряют бой.

При 0 HP урон прекращается; движение и инвентарь пока доступны. Смерть, тела,
возрождение, лечение и использование бинта будут отдельными задачами.
Offline очищает HUD; retry/reload сохраняют здоровье в памяти работающего хоста.
Здоровье не записывается в SQLite: после рестарта хоста снова 100 HP.

### Ближний бой (T019/T020)

Выберите оружие кнопкой «Экипировать…», подойдите к зомби и нажмите F или
«Ударить». Интерфейс показывает подтверждённое сервером оружие и характеристики.

| Оружие  | Урон | Дальность | Пауза | Ударов на 100 HP |
| ------- | ---- | --------- | ----- | ---------------- |
| Дубинка | 34   | 1,8 м     | 0,6 с | 3                |
| Нож     | 20   | 1,2 м     | 0,3 с | 5                |
| Лом     | 40   | 2,2 м     | 0,8 с | 3                |
| Топор   | 60   | 1,6 м     | 1,2 с | 2                |

Сервер выбирает одного ближайшего достижимого зомби, проверяет стены,
экипировку и положительные HP. Промах тоже расходует паузу; смена оружия
сохраняет паузу предыдущего взмаха. Несколько вкладок делят экипировку и cooldown.
Нанесённый урон сохраняется при смене оружия; убитый зомби исчезает.

Каждый персонаж получает стартовый набор отдельно от сетки инвентаря.
Подбор, перенос оружия, стрельба, тела и добыча с зомби пока не реализованы.
При 0 HP экипировка и удар недоступны. Reload/retry восстанавливают экипировку
и состояние зомби из памяти хоста; после рестарта их состояние сбрасывается.
